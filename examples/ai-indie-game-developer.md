# Example: AI indie game developer — comprehensive route A

## Confirmed goal and teaching method
Long-term **Route A: comprehensive AI indie game developer**. Do not restrict the learner to cultivation games, numerical systems or visual novels. The priority is directing AI agents (such as Codex) and a connected toolchain to build **real playable, testable, releasable games**, while understanding game design and technology tradeoffs. Baseline diagnosis → phases/modules → one interactive lesson at a time → assignments and Gates → portfolio/progress record.

## Core competencies and proposed stages
1. **Survey/diagnosis:** genre familiarity, game loops, coding, art/audio, project scoping and AI-agent skills; observe an end-to-end tiny game build.
2. **Game design:** player goals, loops, rules, feedback, progression, level design, probability/balance and playtesting.
3. **Engine selection:** Godot (good general starting point), Ren'Py for visual novels, Web engines, Unity/Unreal where justified. Choose based on genre and distribution, not loyalty to a single engine.
4. **Agentic production:** specifications, task slicing, Git, AI development agents, safe tool permissions, API/MCP/Skills/script orchestration, code/test review.
5. **Asset pipeline:** 2D visual direction, sprites, animation, voice/music/SFX; 3D generation tools such as Tripo followed by Blender cleanup, topology and integration when applicable.
6. **Gameplay implementation:** input, UI, scenes, state, saves, progression, AI, performance, accessibility and analytics where relevant.
7. **QA and balance:** reproducible tests, automated checks, numerical simulation, external playtests, bugs and iteration.
8. **Steam/market:** genre research, demo/store materials, pricing, compliance, launch/marketing and postlaunch decisions.
9. **Portfolio/capstone:** different game types and a polished playable release candidate with documented design and test evidence.

## First observed micro-demo
`凡人修仙：百年筑基` is an **initial small observational demonstration** intended to show how AI actually performs the entire development workflow, not the program's exclusive genre or capstone. Treat it as a proposed demo, **not** evidence a playable game was already produced.

## Interactive first diagnostic
Ask the learner to break down the loop of one familiar game, rank constraints for two engines, identify risks in a feature request, and explain what proof would show that an AI-produced game is actually playable.

## Stage Gate examples
- Design a small game loop and produce a measurable playtest protocol.
- Direct an agent to implement a feature; learner explains architecture and verifies actual behavior.
- Build a complete playable prototype in a deliberately chosen genre/engine.
- Conduct independent playtests, fix defects and justify a release decision.

Skills in the hosting game-development repository may support implementation, but **this tutor skill** governs how learning is assessed.
